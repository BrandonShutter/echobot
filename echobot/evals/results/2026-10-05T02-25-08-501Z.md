```text
Echo images are hosted at `registry.echo.ai`. To pull one, you need a pull token.

*1. Create a pull token*

*2. Log in*
```
echo "$ECHO_PULL_TOKEN" | docker login registry.echo.ai --username <your-org> --password-stdin
```

*3. Pull the image*
```
docker pull registry.echo.ai/python:3.12
```

You can also use it as a base image in a Dockerfile:
```
FROM registry.echo.ai/python:3.12
```

*In Kubernetes*, create an image pull secret:
```
kubectl create secret docker-registry echo-registry \
  --docker-server=registry.echo.ai \
  --docker-username=<your-org> \
  --docker-password="$ECHO_PULL_TOKEN"
```
Then add it to your pod spec:
```
imagePullSecrets: [{ name: echo-registry }]

## pip-with-error: pass

Troubleshooting with the error: documented fix, then a resolution check. Asked by: acme-corp customer, channel shared with acme-corp.

> **question:** pip install fails in python-fips:3.12 with: ValueError: [digital envelope routines] unsupported

**Answer**

```text
That's a known issue (tracked as echo-images#412). One of the packages you're installing calls `hashlib.md5()` without passing `usedforsecurity=False`. FIPS mode is on by default in `python-fips:3.12`, so OpenSSL blocks MD5 there and the call fails instead of falling back to something else.

*Recommended fix:* install your packages in `python:3.12`, which you already use, then copy them into the `python-fips:3.12` image you run in production:

```
FROM registry.echo.ai/python:3.12 AS build
RUN pip install --prefix=/install -r requirements.txt

FROM registry.echo.ai/python-fips:3.12
COPY --from=build /install /usr/local
```

*Another option:* if a newer release of the failing package passes `usedforsecurity=False`, upgrading it fixes the problem.

Don't turn off FIPS mode in the image you run in production. That would undo the reason for using the FIPS image.

If you see the same error when your app *imports* the package in the FIPS image, after the install has worked, then that package doesn't support FIPS. Send me the package name and version and I'll pass it to Echo's team.

Did the multi-stage build fix it?

Sources: <https://mock.echobot.local/docs/images/fips-variants|FIPS image variants>, Echo's image definition for python-fips:3.12, Echo support runbook "Known issue: pip install fails in python-fips images", Echo GitHub issue echo-images#412
For next time: <https://mock.echobot.local/docs/images/fips-variants|FIPS image variants>
```
